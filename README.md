# H3-Go

This library is a pure-Go implementation of the
[H3 Core Library](https://github.com/uber/h3). It needs no C toolchain and no
cgo. For API reference, see the [H3 Documentation](https://h3geo.org/).

**This is v4 of this library, supporting H3 v4.**

Check out [v3](https://github.com/uber/h3-go/tree/v3.7.1) or checkout the git tag for the version you need.

**Migrating from v3?**

Check out [v3 to v4 migration guide](https://h3geo.org/docs/library/migrating-3.x).
There have been no breaking changes to the format of H3 indexes.  Indexes
generated by older versions can be parsed in v4, and vice-versa.

# Usage

## Installation

```bash
go get github.com/uber/h3-go/v4
```

## Quickstart

```go
import "github.com/uber/h3-go/v4"

func ExampleLatLngToCell() {
	latLng := h3.NewLatLng(37.775938728915946, -122.41795063018799)
	resolution := 9 // between 0 (biggest cell) and 15 (smallest cell)

	cell, err := h3.LatLngToCell(latLng, resolution)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Println(cell)
	// Output:
	// 8928308280fffff
}
```

# C API

## Notes

* `LatLng` returns `Lat` and `Lng` as degrees, instead of radians.
* H3 C API function prefixes of `get` have been dropped in support of Golang's
 `Getter` [naming style](https://go.dev/doc/effective_go#Getters).
* Convenience methods have been added to various types where that type was the
  main or only argument.

# Conformance

Since v4.6 the package is pure Go; earlier v4 releases were a cgo binding to
the C library. Its outputs are held to the H3 reference by the conformance
suite in [conformance/](conformance/README.md), whose README states the
contract: discrete outputs (indexes, counts, booleans, errors, sets and
sequences of indexes) are identical to the reference; coordinates agree within
1e-12 degrees of arc and measures within 1e-9 relative; knife-edge inputs,
such as points on cell edges and polygon vertices on cell edges, are outside
the contract. The suite's README also lists where this implementation
deliberately differs from the reference.

The reference sources the suite is generated from are pinned as a git
submodule at `third_party/h3`. They are needed only to regenerate the suite
(`git submodule update --init third_party/h3`, then `go generate
./conformance`), never to build or test the package.
